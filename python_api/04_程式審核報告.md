## 待審區（貼給 Codex 的內容）

需求：`MELE_ALLOWED_ORIGINS` 環境變數從「覆蓋預設清單」改成「附加到基礎清單」，
讓 Vercel production origin（https://mele-chi.vercel.app）永遠被允許，避免 CI 設了
受限清單時把 production 擋掉。標準審核指令見 `團隊\程式審核.md`。

```python
_base_origins = [
    "https://mele-chi.vercel.app",
    "http://localhost:3000",
    "http://localhost:3001",
    "http://localhost:3006",
    "http://localhost:3007",
    "http://127.0.0.1:3000",
    "http://127.0.0.1:3006",
    "http://127.0.0.1:3007",
]
_env_origins = os.environ.get("MELE_ALLOWED_ORIGINS", "").strip()
_extra_origins = [origin.strip() for origin in _env_origins.split(",") if origin.strip()]
allowed_origins = list(dict.fromkeys(_base_origins + _extra_origins))

app.add_middleware(
    CORSMiddleware,
    allow_origins=allowed_origins,
    allow_credentials=False,
    allow_methods=["GET", "POST", "OPTIONS"],
    allow_headers=["Content-Type", "Authorization"],
)
```

## 本次改動本身的判定

- 邏輯正確：env 確實變成「附加」而非「覆蓋」，Vercel production origin 永遠在清單，達成需求。
- `dict.fromkeys` 去重複適當：保序、能去掉 base 與 env 重疊（如 CI 的 localhost），無副作用。
- 無破壞性：舊變數名 `_default_origins` 已無其他地方引用（全檔搜過），不會殘留壞掉的參照。
- `allow_credentials=False`：因此就算 origin 開太寬，也不會有 cookie/session 被盜用的高危風險。

## 給老闆的白話總結

- **這次改的東西是對的、可以上**。原本的 bug（CI 設了環境變數就把 Vercel 正式網站擋在門外）已經修好，正式站永遠進得來。
- 兩個小建議（不急、不擋上線）：
  1. 之後在 Render 設這個環境變數時，**網址結尾不要加斜線**（寫 `https://foo.com`，不要 `https://foo.com/`），否則設了等於沒設。最好的做法是請工程師加一行自動把斜線去掉。
  2. 請工程師加一道保險：**禁止把這個變數設成 `*`**（萬用字元），免得哪天手滑把後端對全世界打開。
- 安全層面：因為這個 API 沒用 cookie 登入（`allow_credentials=False`），即使設定寬鬆也不會有「帳號被盜」這種高危問題，所以可以安心先上、之後再補強。
